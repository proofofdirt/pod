## Objective

Build the cross-platform React Native field agent app — offline-first — including the mandatory **Contract Farming Compliance Module** (Ethiopian Proclamation 578/2008 compliant). This is the human data entry layer that the entire POD Oracle depends on.

The reward reflects that the Contract Farming Compliance Module is legally mandatory for the Ethiopia MVP and cannot be scoped out.

---

## Why This App Exists

Field agents in UKE Welega (West Ethiopia) are the first link in the trust chain. Every Oracle verification starts with a human submitting data — a GPS polygon, a contract document, a livestock photo, an input delivery receipt. The app is what makes that data reliable, timestamped, geotagged, and legally compliant before it ever reaches a satellite.

Without this app, there is no Oracle. Without the Oracle, no tranche disbursements can be approved. The app is as critical as the smart contracts.

> **Architectural constraint (V1):** Ethiopian law prohibits stablecoin/cryptocurrency transactions. The on-chain layer (V1) carries **verified data only** — oracle records, document hashes, tranche approval events, audit logs. All capital into Ethiopia moves as fiat: PODRWA SPV (KSA) → Ethiopian financial institution partner → Turmi (or another Ethiopian operator). Fully on-chain settlement is a V2 goal, contingent on Ethiopian regulation.

## Core Features Required (MVP)

### 1. Contract Farming Compliance Module (MANDATORY)

This is the highest-priority feature. Every funded plot must have a registered contract before vault activation.

**Required workflows:**

**Contract Generation & Signing:**
- Generate legally-formatted PDF from Proclamation 578/2008 templates
- Templates in three languages: English, Amharic, Oromifa
- Digital signature capture: biometric fingerprint (preferred) or OTP via SMS
- Generated PDF is hashed, uploaded to IPFS, and hash is sent to Oracle API for on-chain anchoring

**Land Rights Capture:**
- Photo capture of land use rights certificate / Kebele-issued land documentation
- OCR extraction of key fields (optional — OCR in `oracle/api/contract-farming/`)
- Encrypted local storage (AES-256) — only Turmi and the producer hold decryption access

**Woreda Registration:**
- Generate Woreda registration package (PDF summary of plot + farmer + contract)
- Workflow for submitting to Woreda office (QR code for digital Woreda receipt)
- Capture and store Woreda confirmation receipt scan

**Input Delivery Receipt:**
- GPS capture at point of delivery
- Photo capture (proof of delivery)
- Timestamp and agent signature
- Item checklist: seed type + quantity, fertiliser, tractor service record
- This receipt triggers Oracle API notification which feeds into the tranche approval flow (fiat wire executed off-chain by PODRWA SPV)

### 2. GeoJSON Plot Boundary Collection

- Interactive map (react-native-maps) for GPS polygon capture
- Minimum area validation: **plots must be ≥ 1 ha** — the tech works at plot level; financing minimums per farm are an economics setting decided by the DAO per stage (agent + infrastructure cost), not a tech limit
- GPS accuracy check: flag and prompt re-capture if accuracy > 5 metres
- Cooperative member plot tagging: show running aggregate of member plots vs the current financing minimum
- Offline polygon storage and batch upload queue

### 3. Livestock Body Condition Scoring

- Guided photo capture workflow (lateral view instructions with overlay guide)
- Geotagged JPEG capture: GPS + timestamp + agent ID embedded in metadata
- On-device BCS inference using ONNX/TFLite model from `oracle/satellite/bcs/` (coordinate with BCS-005 bounty claimant)
- Display preliminary BCS score to agent before upload
- Flag workflow: agents can flag welfare concerns with a single tap; flags escalate to Turmi vet coordinator

### 4. Activity Log & Sync

- Offline queue for all data submissions (contracts, GeoJSON, photos, receipts)
- Authenticated sync to Oracle API when connectivity returns
- Sync status indicators: queued / syncing / confirmed
- Conflict resolution for overlapping agent submissions

### 5. Agent Dashboard

- Plot registry: all plots assigned to the agent with current Oracle status
- Outstanding actions: plots needing contract signing, photos due, deliveries to log
- Earnings tracker: verified submissions and accrued earnings shown in **ETB** (field agents are paid in local currency by Turmi — no wallets or tokens in the agent flow; read from Oracle API)

## Offline-First Architecture

**Non-negotiable:** All primary workflows must complete without internet connectivity. This means:

- Contract PDF generation must run entirely on-device (no server dependency)
- Digital signature capture: offline biometric / OTP must work without server round-trip
- GeoJSON capture: full offline storage before any sync
- BCS scoring: on-device model inference (ONNX Runtime or TFLite)
- Queue depth: must handle ≥500 queued submissions without performance degradation

Reconnection sync must handle partial uploads gracefully (no duplicate submissions).

## Integration Points

**`oracle/api/`** — All submissions sync to the Oracle API. Familiarise yourself with the API schema in that sub-repo (or coordinate with the API contributor).

**`oracle/satellite/bcs/`** — The BCS model (BOUNTY-005) produces an ONNX/TFLite artifact that this app integrates. Coordinate with the BCS-005 claimant on the model interface.

**`oracle/api/contract-farming/`** — Contract templates and registry anchoring are defined here. The app consumes the template JSON schemas and sends IPFS hashes back to the Oracle API.
